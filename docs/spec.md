## Problem Statement

我要在 thingnario（能源 IoT 數據新創）Data Product Manager 實體面試中，用 20–30 分鐘介紹我在前公司主導設計的「新北市營建工程污染削減監測儀表板與申報前管制機制」。原系統屬前公司與機關，無法展示真實畫面與數據；純投影片又無法讓面試官體會「從行政區下鑽到工地」與「申報時即時判定是否觸發」的產品手感。面試現場網路不可靠，投影解析度未知（1920×1080 或 1366×768），操作失誤或畫面溢出會直接影響專業形象。

## Solution

一個離線可用的單一 HTML 簡報網站，包含：

- **簡報模式**：固定 8 頁，鍵盤翻頁、頁碼、全螢幕，16:9 版面在兩種解析度下都清楚可讀。
- **儀表板 Demo**（第 3 頁，亦可由導覽列直接進入）：以模擬數據重現新北市 29 區削減率地圖、tooltip、點擊下鑽 TOP 10 工地、優先輔導標示、申報前管制啟動狀態、新申報案件觸發判定面板。
- **附錄**：人口密度分區圖，用於回答分區與手動調整的提問。

模擬數據以固定亂數種子產生，每次開啟結果一致，並滿足指定的敘事不變量：全市削減率 68.5%（高於環境部 115 年目標 65%），但以自訂分區目標檢視有 4 區未達標，且未達標主因是區內大規模工程削減不足——由此導出「申報前管控大規模工程」的必要性。

## Implementation Decisions

### 技術基礎
- Vite + React + TypeScript；以 vite-plugin-singlefile 輸出單一 HTML，所有 JS／CSS／地圖資料內嵌。
- 不使用任何外部 CDN、圖磚或線上字型；字型堆疊為 "PingFang TC", "Microsoft JhengHei", "Noto Sans TC", sans-serif。
- 地圖以 d3-geo 投影繪製 SVG，不使用 Leaflet。圖表（附錄）以 SVG 自繪或 d3-scale 輔助，不引入大型圖表庫。

### 地圖資料
- 來源：內政部國土測繪中心「鄉鎮市區界線（TWD97 經緯度）」SHP（data.gov.tw 資料集 7441，版本 1140318）。
- 一次性前處理：篩選 COUNTYNAME = 新北市 的 29 區 → 轉 GeoJSON → 簡化幾何（目標內嵌大小 < 200 KB）→ 以行政區名稱為鍵納入專案。前處理腳本保留在 repo，原始 SHP 不入庫。
- 地圖角落標示資料來源。

### 模組劃分
1. **設定（config）**：唯一的手動編輯入口。結構包含：
   - 年度（115）、環境部年度目標（115: 65%、116: 67%）
   - 分區定義：都會／發展／偏鄉的人口密度門檻（≥10,000；1,500–10,000；<1,500）與分區目標（70／67／65%）
   - 29 區清單：名稱、人口密度、分區、`manualAdjusted`、調整原因
   - 未達標行政區與其指定削減率（新莊 66.8、三重 68.1、林口 63.5、淡水 64.2）
   - 達標區削減率範圍（目標 +1% 至 +10%）
   - 全市削減率目標值（68.5%）
   - 各分區工地數範圍（40–90／20–60／3–15）
   - 前 10 大工程配置（新莊 1、三重 1、林口 2、淡水 2、板橋 1、新店 1、土城 1、中和 1）與占全市排放比例（約 80%）
   - 本年度預估觸發案件數（7）
   - 亂數種子
2. **領域核心（純函式，無 UI 依賴）**：
   - 資料集產生：輸入 config 與種子，輸出行政區彙總（工地數、排放量、削減量、削減率、分區目標、是否未達標）、工地清單（代號、行政區、工程類型、排放量、削減量、削減率）、全市削減率。
     - 排放量採長尾分布；前 10 大工程依配置落點，合計約 80%。
     - 未達標區的大工程削減率多低於目標；達標區大工程高於目標。
     - 每區削減量由該區指定削減率反推並分配至工地，使行政區彙總精確等於設定值；全市削減率經排放量加權精確為 68.5%（產生器須調整非大工程工地的權重或達標區削減率以滿足此約束）。
     - 4 個未達標區的 TOP 10 中至少 3 處削減率低於分區目標。
   - 申報判定：輸入申報案件（行政區、面積、工期月數、外運土石 m³、合約經費萬元、是否需建照）與行政區彙總，輸出：三項大規模條件各自是否成立與法規依據、是否為大規模工程、行政區是否未達標、是否觸發、應檢附文件清單。所有門檻以「≥」判定；合約經費門檻為 20,000 萬元。
   - 工具：TOP N 排序、優先輔導判定、數值格式化。
3. **簡報外殼**：頁面狀態（目前頁、是否在附錄、進入附錄前的頁碼）、鍵盤處理（輸入元素聚焦時忽略快捷鍵）、全螢幕、頁首導覽列、頁碼。16:9 畫布以等比縮放適配視窗。
4. **儀表板**：摘要卡列；左側約 45% 地圖；右側約 55% 兩個分頁（TOP 10 工地／新申報案件模擬）。地圖點擊：設定選取行政區 → 切到 TOP 10 分頁 → 同步模擬面板行政區。初始顯示全市 TOP 10（含行政區欄），不附「占 8 成」說明文字。
5. **八頁簡報內容與附錄**：各頁為靜態內容元件；第 2 頁規則摘要卡與附錄圖從 config 讀值，避免與儀表板不一致。

### 固定分類
- 工程類型 6 類：建築（RC/SRC）、道路／隧道、捷運／軌道、區段徵收／重劃、管線、橋梁／水利。僅「建築（RC/SRC）」屬房屋建築工程。前 10 大以捷運／軌道、區段徵收／重劃、大型建築為主。
- 工地代號：「工地 {分區字母}-{三位流水號}」，A 都會、B 發展、C 偏鄉，全市連號。

### 情境按鈕預設值
- 未達標區 × 大規模 × 房屋建築 → 觸發，應交兩份文件。
- 未達標區 × 非大規模 → 不觸發。
- 達標區 × 大規模 → 不觸發。

### 部署
- GitHub Actions：push 至 main → 安裝、測試、建置 → 發布 GitHub Pages；打 tag 時將單一 HTML 附於 Release。
- repo 為 public；Pages Source 需由使用者於 repo 設定改為「GitHub Actions」。

## Testing Decisions

- 好的測試只驗證外部可觀察行為（給定輸入的輸出、使用者看到與可操作的結果），不驗證內部實作（如亂數分配細節、元件內部 state）。
- **接縫 1：領域核心（Vitest）**
  - 資料集產生不變量：未達標區恰為新莊、三重、林口、淡水且削減率等於設定值（容差 0.05%）；其餘 25 區落在目標 +1%～+10%；全市削減率 68.5%；前 10 大占總排放 78–82% 且落點符合配置；各分區工地數在範圍內；4 個未達標區 TOP 10 優先輔導 ≥ 3；同種子兩次產出深度相等；工地代號格式與分區字母一致；29 區齊全且名稱與地圖資料鍵一一對應。
  - 申報判定：至少 8 組組合（達標／未達標 × 大規模／非大規模 × 房屋建築／非房屋建築）的觸發結果與應檢附文件；三項大規模條件各自的邊界值（恰好等於、差 1）；條件 1 需面積與工期同時成立；任一條件成立即為大規模工程。
- **接縫 2：建置後單一 HTML（Playwright）**
  - 以 file:// 開啟並阻擋所有網路請求，驗證地圖、儀表板、翻頁正常且無主控台錯誤。
  - 1366×768 與 1920×1080 下逐頁（含附錄）檢查無元素溢出其容器、文字不重疊。
  - 鍵盤：← / → 翻頁與邊界、A 進出附錄回到原頁、附錄中 ← / → 無作用、輸入框聚焦時快捷鍵無作用。
  - 儀表板互動：hover 顯示 tooltip 內容、點擊行政區顯示該區 TOP 10 並同步模擬面板、返回全市、三個情境按鈕的判定結果。
- UI 元件不另寫單元測試。專案目前無既有測試可參照，上述兩個接縫即為先例。

## Out of Scope

- 真實資料串接、MS SQL Server、後端 API（第 6 頁僅以架構圖說明）。
- 實際申報流程、文件上傳與回傳現場查核專案的功能實作。
- 116 年度切換或多年度比較（config 保留 116 年目標值，但畫面只呈現 115 年）。
- 講者備註、簡報計時器、行動裝置最佳化、深色模式。
- 新增第 9 頁以後的簡報頁面；附錄以外的額外補充頁。
- 「前 10 大工程占 8 成」與「預估觸發件數估算依據」的文字說明（由簡報者口頭回答）。
